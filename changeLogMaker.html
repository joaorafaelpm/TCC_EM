Passo 1 de 6
Organização
de Pastas

Antes de escrever código, é importante saber onde cada arquivo vai. Segurança não fica em components/ — ela fica em pastas separadas por responsabilidade.

Estrutura que você vai criar arquivos novos
src/ ├── services/ ← camada de comunicação HTTP │ └── api.js axios + interceptors │ ├── utils/ ← funções puras reutilizáveis │ ├── token.js get/set/clear JWT │ ├── validators.js validações de formulário │ └── logger.js console seguro │ ├── hooks/ ← hooks customizados (você já tem) │ ├── useAuth.js │ ├── useHasAuthority.js ← já existe │ └── useFormValidation.js │ ├── components/ │ └── shared/ ← componentes reutilizáveis │ └── ProtectedRoute.jsx │ └── pages/ ← suas páginas (já existem)
Por que essa divisão?
Pasta Responsabilidade Regra
services/ Toda comunicação com APIs externas Nenhum componente faz fetch ou axios direto
utils/ Funções sem estado, sem JSX Não importam hooks, não renderizam nada
hooks/ Lógica com estado reutilizável Sempre começam com use
components/shared/ Componentes usados em múltiplas páginas Não contêm lógica de negócio
⚠
Não coloque segurança dentro de componentes de página. Se você valida direto no LoginPage.jsx, vai acabar copiando e colando a mesma lógica em RegisterPage.jsx, CheckoutPage.jsx etc. Centralize em utils/ e hooks/.

Passo 2 de 6
Serviço HTTP
com Axios

Esse é o arquivo mais importante — é a base de toda a segurança HTTP. Ele cuida de anexar o token, tratar expiração e redirecionar em caso de erro de autorização.

novo src/services/api.js
src/services/api.js criar do zero
import axios from 'axios'; import { getToken, clearToken } from '../utils/token'; // Cria uma instância configurada do Axios const api = axios.create({ baseURL: import.meta.env.VITE_API_URL, timeout: 10000, // 10s — evita requests pendurados headers: { 'Content-Type': 'application/json', }, }); // ── REQUEST: anexa o JWT em toda requisição ────────── api.interceptors.request.use( (config) => { const token = getToken(); if (token) { config.headers['Authorization'] = `Bearer ${token}`; } return config; }, (error) => Promise.reject(error) ); // ── RESPONSE: trata erros globalmente ──────────────── api.interceptors.response.use( (response) => response, // sucesso: passa direto (error) => { const status = error.response?.status; if (status === 401) { // Token expirado ou inválido clearToken(); window.location.href = '/login?expired=true'; } if (status === 403) { // Autenticado, mas sem permissão window.location.href = '/403'; } // Repassa o erro para o catch local do componente return Promise.reject(error); } ); export default api;
Como usar nos componentes substituir fetch/axios direto
Antes (direto no componente) ❌ evitar
// LoginPage.jsx — NÃO faça isso const res = await axios.post('http://localhost:8080/auth/login', data);
Depois (usando o serviço) ✓ correto
// LoginPage.jsx — faça assim import api from '../services/api'; const res = await api.post('/auth/login', data); // URL relativa — a baseURL já está no api.js
💡
Com o interceptor de response, você não precisa mais checar status 401 em cada componente. O redirecionamento acontece automaticamente. Nos componentes, você só trata os erros de negócio (ex: "senha incorreta", "e-mail já cadastrado").

// Regras de validação puras — sem estado, sem React export const required = (value, label = 'Campo') => !value?.toString().trim() ? `${label} é obrigatório` : null; export const email = (value) => !/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value) ? 'E-mail inválido' : null; export const minLength = (min) => (value) => value?.length < min ? `Mínimo ${min} caracteres` : null; export const maxLength = (max) => (value) => value?.length > max ? `Máximo ${max} caracteres` : null; export const noScript = (value) => /<script/i.test(value) ? 'Conteúdo inválido' : null; // Combina várias regras em um campo export const validate = (value, rules) => { for (const rule of rules) { const error = rule(value); if (error) return error; } return null; };
novo src/hooks/useFormValidation.js
src/hooks/useFormValidation.js criar do zero
import { useState } from 'react'; export function useFormValidation(schema) { const [errors, setErrors] = useState({}); // Valida todos os campos contra o schema const validateAll = (data) => { const newErrors = {}; for (const [field, rules] of Object.entries(schema)) { const error = rules.reduce((acc, rule) => acc || rule(data[field]), null); if (error) newErrors[field] = error; } setErrors(newErrors); return Object.keys(newErrors).length === 0; }; // Adiciona um erro vindo do backend const setBackendError = (err) => { const msg = err.response?.data?.message || err.response?.data?.error || 'Erro inesperado. Tente novamente.'; setErrors((prev) => ({ ...prev, general: msg })); }; const clearErrors = () => setErrors({}); return { errors, validateAll, setBackendError, clearErrors }; }
Usando no componente de login exemplo real
src/pages/LoginPage.jsx exemplo de uso
import api from '../services/api'; import { useFormValidation } from '../hooks/useFormValidation'; import { required, email, minLength } from '../utils/validators'; const schema = { email: [required, email], password: [required, minLength(6)], }; export function LoginPage() { const [form, setForm] = useState({ email: '', password: '' }); const [loading, setLoading] = useState(false); const { errors, validateAll, setBackendError, clearErrors } = useFormValidation(schema); const handleSubmit = async (e) => { e.preventDefault(); clearErrors(); if (!validateAll(form)) return; // ← para aqui se inválido setLoading(true); try { const { data } = await api.post('/auth/login', form); setToken(data.token); // redireciona... } catch (err) { setBackendError(err); // exibe a mensagem do seu backend } finally { setLoading(false); } }; return ( <form onSubmit={handleSubmit}> {errors.general && <div role="alert" className="error">{errors.general}</div>} <input value={form.email} onChange={...} /> {errors.email && <span>{errors.email}</span>} <button disabled={loading}>{loading ? 'Aguarde...' : 'Entrar'}</button> </form> ); }

Passo 4 de 6
Tokens e
Armazenamento

O token JWT é o item mais sensível do frontend. Um arquivo centralizado decide onde ele fica e facilita mudar de estratégia depois.

Comparativo de onde guardar o JWT
Local Vulnerabilidade Veredicto
localStorage Atacável por qualquer XSS, não expira Evitar para tokens
sessionStorage Atacável por XSS, mas limpa ao fechar aba Aceitável agora
Variável em memória Imune a XSS, perde no reload Ideal para access token
Cookie httpOnly Imune a XSS — backend controla Melhor opção (requer mudança no backend)
novo src/utils/token.js
src/utils/token.js criar do zero
// Abstrai onde o token fica — fácil de trocar a estratégia depois let _token = null; // em memória (preferido) export const setToken = (token) => { _token = token; // sessionStorage como fallback para reload de página sessionStorage.setItem('pendezza_token', token); }; export const getToken = () => _token || sessionStorage.getItem('pendezza_token'); export const clearToken = () => { _token = null; sessionStorage.removeItem('pendezza_token'); }; // Verifica se o token ainda é válido pela data de expiração export const isTokenExpired = () => { const token = getToken(); if (!token) return true; try { const payload = JSON.parse(atob(token.split('.')[1])); return payload.exp * 1000 < Date.now(); } catch { return true; } };
✗
Nunca guarde no localStorage: senhas (mesmo hasheadas), dados de cartão de crédito, CPF, endereços completos, ou qualquer dado pessoal sensível. O localStorage sobrevive a logout, reinicialização e é acessível por qualquer script na página.
⚠
Não decodifique o JWT no frontend para tomar decisões de segurança. Use apenas para checar expiração ou exibir o nome do usuário. A validação real acontece no backend a cada request.

Proteção
de Rotas

Um guard de rota que funciona em dois níveis: bloqueia usuários não autenticados e bloqueia usuários sem a authority necessária.

novo src/components/shared/ProtectedRoute.jsx
src/components/shared/ProtectedRoute.jsx criar do zero
import { Navigate, useLocation } from 'react-router-dom'; import { useAuth } from '../../hooks/useAuth'; export function ProtectedRoute({ children, requiredAuthority }) { const { user, isLoading } = useAuth(); const location = useLocation(); // Aguarda verificação inicial do token if (isLoading) return <div>Carregando...</div>; // Não autenticado → vai para login, guarda a URL para redirecionar depois if (!user) { return <Navigate to="/login" state={{ from: location }} replace />; } // Autenticado mas sem a authority necessária → 403 if (requiredAuthority && !user.authorities?.includes(requiredAuthority)) { return <Navigate to="/403" replace />; } return children; }
Configurando as rotas editar seu router
src/App.jsx (ou seu router) exemplo de uso
import { ProtectedRoute } from './components/shared/ProtectedRoute'; // Rotas públicas — qualquer um acessa <Route path="/login" element={<LoginPage />} /> <Route path="/cardapio" element={<MenuPage />} /> // Rotas protegidas — precisa estar logado <Route path="/pedidos" element={ <ProtectedRoute> <MeusPedidosPage /> </ProtectedRoute> } /> // Rotas de gerência — precisa da authority específica <Route path="/admin/restaurante" element={ <ProtectedRoute requiredAuthority="GERENCIA_RESTAURANTE"> <RestauranteAdminPage /> </ProtectedRoute> } /> <Route path="/admin/pedidos" element={ <ProtectedRoute requiredAuthority="GERENCIA_PEDIDOS"> <PedidosAdminPage /> </ProtectedRoute> } />
💡
O state={{ from: location }} salva a URL que o usuário tentou acessar. Na página de login, você pode redirecionar de volta depois do login com navigate(location.state?.from || '/').
